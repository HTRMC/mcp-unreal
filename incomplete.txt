mcp-unreal — what UE 5.8 can do that the MCP cannot do yet
==========================================================

Written 2026-09-06 against v0.3.1 (116 tools, 99 McpLink routes) and the
Launcher 5.8 engine on D:. Every "engine entry point" below was grepped in
the installed engine source; anything not checked is marked (verify).

Rule for everything in this file: python_exec, call_function/set_property on
raw objects, run_console_command and toolset_ops (Epic's Toolset Registry
bridge) are the absolute last fallback. Each item is meant to become its own
McpLink route (game thread, FMcpResponder, FScopedTransaction, remediation
text) plus a Rust tool with a validated vocabulary.

Legend
  UE can        what the editor or engine does today
  McpLink today what the closest existing tool covers (partial coverage)
  Entry points  engine API a native route would call
  Home          which plugin module / route / Rust tool it belongs in
  Headless      whether the E2E can run under -nullrhi


======================================================================
PART A — EDITOR WORKFLOWS WITH NO FIRST-CLASS TOOL (highest value)
======================================================================

A1. Scene / physics queries
  UE can        Line trace, sweep (sphere/box/capsule) and overlap against the
                editor world or the PIE world, by trace channel, object type
                or collision profile, single or multi, with per-hit actor,
                component, location, normal, distance, bone name and face
                index. Also "what is under this screen point" and component
                sweeps.
  McpLink today Nothing exposed. Line traces exist only inside
                editor_ops snap_to_floor and foliage_ops scatter.
  Entry points  UWorld::LineTraceSingleByChannel / LineTraceMultiByChannel /
                LineTraceSingleByObjectType / LineTraceSingleByProfile,
                UWorld::SweepSingleByChannel / SweepMultiByChannel,
                UWorld::OverlapMultiByChannel / OverlapMultiByObjectType,
                UWorld::ComponentSweepMultiByChannel /
                ComponentOverlapMultiByChannel (all UE_API on UWorld,
                Engine/Classes/Engine/World.h), FCollisionShape::MakeSphere/
                MakeBox/MakeCapsule, FCollisionQueryParams (ignore actors,
                trace complex, return physical material).
  Home          McpLinkEditor, /api/world/query, Rust tool physics_query
                (operation: line_trace | sweep | overlap | under_cursor;
                world: editor | pie).
  Headless      Yes (collision does not need an RHI).

PART C — LIMITS OF MODALITY (routes cannot fix these)
======================================================================
C1. Interactive brush tools: Modeling Mode sculpt / cube grid / poly
    edit, landscape sculpt and paint brushes, foliage paint, mesh paint
    brushes. Their *results* are reachable (Geometry Script, raw height
    arrays, vertex colors); the strokes are not. A12 and A13 reimplement
    the useful kernels as operations rather than driving the modes.
C2. Modal dialogs on the game thread wedge a headless editor. Known
    ones: level instance create (Save As), IAssetTools::RenameAssets when
    CDOs reference the asset, IAssetTools::MigratePackages default path,
    some importers' option dialogs. GIsRunningUnattendedScript is set for
    every handler; anything that still prompts must be routed through the
    non-prompting overload or refused when FApp::CanEverRender() is false.
C3. Needs an RHI: capture_viewport, movie_render (both pipelines), Niagara
    spawning, widget animation playback, Slate rasterisation
    (screenshots, AutomationDriver clicks), landscape edit-layer merges,
    ProfileGPU, texture baking through render targets. The E2E for those
    runs on UnrealEditor.exe -unattended, never -nullrhi.
C4. Needs hardware or an external process: Live Link real sources,
    Media IO, Virtual Camera, DMX, MIDI, Multi-User, Switchboard, Learning
    Agents and ML Deformer training, Pixel Streaming clients, device
    deploys, Turnkey installs.
C5. Compile-time changes: Blueprint nativization is gone; C++ edits still
    need a rebuild (build_project / live_coding_ops), and a plugin change
    in the .uproject needs an editor restart (project_ops says so).
