mcp-unreal — gaps
=================

What this MCP cannot do in UE5 yet, as of 2026-09-04 (83 tools, 67 plugin routes).

"Cannot" here means "has no dedicated tool". Several of these are reachable
unstructured through the escape hatches — get_property / set_property /
call_function (any UPROPERTY / UFUNCTION via reflection), asset_ops create (any
factory-backed asset shell), run_console_command, and python_exec (anything the
`unreal` module exposes). What is listed below has no first-class, verified path.


ANIMATION & CHARACTERS
----------------------
- IK Rig, IK Retargeter, Control Rig, Pose Search / Motion Matching: nothing.
- Pose Assets: no creation or pose editing.
- No morph target authoring (they can be listed, not created or edited).
- Anim Sequences themselves: bone track data is read-only (no retargeting, no
  key editing, no additive-from-pose baking).


PHYSICS & DESTRUCTION
---------------------
- Chaos: Geometry Collections, fracturing, destruction fields, Chaos Vehicles,
  Chaos Cloth — none.
- Physics on actors/components is only reachable as properties (physics_asset_ops
  covers ragdoll bodies and constraints).


RENDERING & CINEMATICS OUTPUT
-----------------------------
- Movie Render Graph (the newer node-based pipeline) is not exposed; the
  queue-and-config pipeline is.
- No scene-capture helpers (SceneCapture2D actors are properties only).
- capture_viewport is one JPEG from a windowed editor — no headless capture, no
  video, no viewport-layout control.
- Rendering needs a windowed editor: the Movie Render Queue runs through PIE.


MATERIALS & TEXTURES
--------------------
- Material Layers and layer blends: material_function covers Material
  Functions, not the layer stack.
- Textures: no import-free authoring from raw pixels, and no pixel writes to an
  existing texture (render targets bake into one instead). Compression/LOD
  settings only via set_property.
- No vertex painting. No decal-specific tooling.


NIAGARA
-------
- No scratch pad or custom module scripts: niagara_author places existing module
  scripts in a stack but cannot author a new module's own graph.
- No simulation stages, event handlers or parameter-definition assets.
- Dynamic inputs on a module input (only literal values are settable).


AI
--
- EQS (Environment Query System): nothing. The EQS editor plugin exports no
  symbols, and its graph — not UEnvQuery::Options — is the source of truth, so
  authoring options directly would be discarded the next time the asset opens.
- Smart Objects, Mass Entity: nothing.
- Nav modifiers and nav-link authoring: nothing (queries and the mesh build are
  covered).
- State Tree task/condition *parameters* are instanced-struct data with no
  first-class editor here; the nodes can be added, not tuned.
- AI Perception only via properties.


WORLD BUILDING
--------------
- World Partition: no streaming sources, no runtime cell inspection, no
  conversion of a plain map into a partitioned one.
- Level Instance creation needs a windowed editor (the engine hardcodes a Save
  As dialog); editing a level instance in place is not exposed.
- Landscape: no splines, no grass-type wiring, no sculpt/erosion brushes (only
  raw height writes + layer paint), no landscape material tooling.
- No BSP/geometry editing (only build_level geometry), no modeling-mode tools,
  no Geometry Script / dynamic meshes, no UV editing or generation beyond
  lightmap UVs, no procedural mesh creation from scratch.


AUDIO
-----
- No audio modulation. No submix effect-chain authoring (asset + properties
  only).
- No playback verification or audio capture — you cannot "hear" the game.
- MetaSound presets, pages and variables are not exposed (graphs, nodes,
  connections and interface members are).


EDITOR WORKFLOW
---------------
- The editor UI is read-only: ui_query inspects Slate/UMG trees but nothing
  clicks a button, drags a widget, or opens an asset editor. Input injection is
  PIE-only, not editor-UI.
- Debugging: no Blueprint breakpoints, stepping or watch values. No Gameplay
  Debugger, Visual Logger, or network profiler.
- Localization gather/compile run as commandlets (a separate editor process),
  so they cannot be driven from inside a running editor session.
- No translation editing: the .archive entries themselves are not exposed, and
  there is no import/export of PO files or dialogue scripts.
- Source control: no changelist management, no shelving, no diff/history
  (status, checkout, add, delete, revert, sync and submit are covered).


BUILD, PACKAGE, C++
-------------------
- No Live Coding / hot-reload trigger.
- project_ops only reads project info and toggles plugins — no target editing
  beyond raw ini (code_ops covers module creation).


PROFILING
---------
- No stat readback beyond perf_ops frame_stats. No memreport, no GPU profile, no
  LLM / memory-tag stats.


ECOSYSTEM PLUGINS WITH NO INTEROP
---------------------------------
LiveLink, nDisplay / virtual production, Datasmith / CAD import, Groom (hair),
Water & Landmass, Take Recorder, RealtimeMesh (third-party, deliberately
excluded).


STRUCTURAL LIMITS
-----------------
Not feature gaps, but still "cannot":

- UE 5.8 only. 5.7 and earlier will not compile (5.8 APIs + C++23).
- The prebuilt plugin is Windows-only; other platforms build from source.
- Editor tools need a running editor, one per port 8091 — two instances fight
  over the port.
- Loopback only, no authentication: cannot drive an editor on another machine.
- Cannot drive a packaged or standalone build. input_inject and player_control
  require PIE inside the editor.
- Headless (-nullrhi) blocks capture_viewport, Niagara spawning, and
  widget-animation playback.


LARGEST COHERENT HOLES
----------------------
If picking next work:

1. Material Layers and layer blends
2. Blueprint debugging (breakpoints, stepping, watch values)
3. Chaos destruction (Geometry Collections, fracturing)
4. Translation editing (archive entries, PO import/export)
5. EQS (needs the EQS editor plugin's unexported graph classes)
