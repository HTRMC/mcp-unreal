1. Epic's own agent surface in 5.8

  Bridged 2026-09-06: toolset_ops (plugin/McpLinkToolsets) lists, describes and executes every toolset in the Toolset Registry — Epic's, project-authored UToolsetDefinition classes, Python toolsets — and reads UAgentSkill
  assets. The Unreal MCP plugin (Streamable HTTP, port 8000) is a second transport onto the same registry, so an agent that wants it can connect to it directly; nothing to bridge.

  2. Engine systems with no route at all

  Status after 2026-09-06. Everything below is either done, reachable through the generic tools with the recipe given, editor-UI-only, or still a real gap.

  Done today (each has a tool, fixtures and docs):
  - Control Rig assets, hierarchies and Sequencer tracks (control_rig_ops); IK Rig, IK Retargeter and batch retargeting (ik_rig_ops); Pose Assets (pose_asset_ops); Mirror Data Tables
    (mirror_table_ops); Animation Modifiers (anim_asset_ops apply_modifier); morph targets, clothing and skin weights (skeletal_mesh_ops).
  - Landscape edit layers, splines and grass types (landscape_ops); runtime virtual textures (rvt_ops); HLOD generation, minimap and nav-data builds (world_partition_build); Geometry Script
    (geometry_script_ops).
  - Material Parameter Collections (material_parameter_collection_ops); cube and volume textures (texture_ops); Media Framework (media_ops).
  - Movie Render Graph (movie_render); Level Snapshots (level_snapshot_ops); replays (replay_ops); net emulation and previews (pie_control).
  - Interchange import (asset_ops import interchange=true); glTF and any registered exporter (asset_ops export format).
  - Editor Utility Blueprints and Widgets, collections, the Asset Manager, Live Coding, the DDC, String and Curve Tables (the pipeline tools); the Toolset Registry (toolset_ops).
  - Remote Control presets (remote_control_ops); Live Link sources, virtual subjects and presets (live_link_ops); Motion Matching schemas, databases and index builds (pose_search_ops);
    Mass Entity configs, traits, spawners with a built-in radius/points generator, and spawning in PIE (mass_ops).
  - Control Rig graph authoring (rigvm_graph_ops); Choosers (chooser_ops); Gameplay Cameras (gameplay_camera_ops); linked anim layers and Animation Layer Interfaces
    (anim_blueprint_modify create_layer_interface / implement_layer_interface / add_linked_layer_node).

  Reachable through the generic tools (spawn_actor, set_property, call_function, blueprint_modify, asset_ops) — no dedicated route, and none planned unless a recipe proves awkward:
  - Water: spawn_actor WaterBodyLake / WaterBodyRiver / WaterBodyOcean (Water plugin), then call_function AddSplinePoint on its WaterSpline component and set_property the WaterBodyComponent.
  - Smart Objects and Zone Graph: asset_ops create SmartObjectDefinition + set_property Slots; spawn_actor ZoneShape + set_property Points on its ZoneShapeComponent (plugins off by default).
  - Mover: blueprint_modify add_component MoverComponent (or CharacterMoverComponent) + set_property; Motion Warping: anim_notify_ops add_notify_state AnimNotifyState_MotionWarping.
  - Post-process material chains: set_property Settings.WeightedBlendables on a PostProcessVolume; Substrate: material_graph add_expression MaterialExpressionSubstrate*; the path tracer:
    movie_render with MoviePipelineDeferredPass_PathTracer or the r.PathTracing cvars; GPU Lightmass: enable the plugin and build_level lighting uses it.
  - Sparse volume textures and OpenVDB, Alembic and Geometry Cache, grooms: asset_ops import once the importer plugin is enabled. Paper2D sprites and Text3D: asset_ops create / spawn_actor + set_property.
  - Audio Modulation, WaveTable, Soundscape and Synesthesia assets: asset_ops create + set_property; Quartz: call_function on the Quartz subsystem in PIE.
  - Chaos Vehicles: blueprint_modify add_component ChaosWheeledVehicleMovementComponent + set_property; Physics Control: add_component PhysicsControlComponent + call_function in PIE;
    Chaos Caching: spawn_actor ChaosCacheManager + set_property ObservedComponents and CacheCollection, then call_function in PIE.
  - Day Sequence: spawn_actor DaySequenceActor + call_function SetTimeOfDay; Take Recorder: call_function on TakeRecorderBlueprintLibrary (windowed editor); camera rigs: spawn_actor
    CameraRig_Rail / CameraRig_Crane; Template and Actor Sequences: sequence_ops (any UMovieSceneSequence).
  - USD: spawn_actor UsdStageActor + set_property RootLayer; Datasmith: call_function on DatasmithSceneElement statics (plugins off by default).
  - HLOD layers: asset_ops create HLODLayer + set_property; Common UI widgets: widget_blueprint_modify add_widget with the CommonUI classes.
  - Iris, Replication Graph, Pixel Streaming and Multi-User settings: config_ops on DefaultEngine.ini; Gameplay Debugger: run_console_command EnableGDT in PIE.
  - Landscape patches (LandscapePatch plugin, off by default): there is no patch actor — spawn_actor Actor, add_component LandscapeCircleHeightPatch (Radius, Falloff) or
    LandscapeTexturePatch (SetHeightTextureAsset / SetHeightSourceMode / SetBlendMode via call_function), then call_function AssignToLandscape(Landscape, EditLayerName) — the patch
    edit layer is created for you.
  - PCG Biome Core (off by default) is content, not classes: spawn_actor /PCGBiomeCore/Blueprints/BP_PCGBiomeCore.BP_PCGBiomeCore_C (a PCGComponent on BiomeCore), the volume /
    spline / texture / exclusion shape Blueprints, and asset_ops duplicate of the DefaultBiome / DefaultGenerator / DefaultAsset templates for data; pcg_ops generates.
  - Wave Function Collapse (off by default): asset_ops create WaveFunctionCollapseModel + set_property TileSize / Constraints, then call_function Collapse(TryCount, Seed) on the
    WaveFunctionCollapseSubsystem after set_property WFCModel / Resolution / OriginLocation on it (the BP library only derives models).
  - Buoyancy (Water plugin): add_component BuoyancyComponent + set_property BuoyancyData.Pontoons [{RelativeLocation, Radius}], BuoyancyCoefficient, BuoyancyDamp on a simulating actor.
  - Game Features / Modular Gameplay (off by default): asset_ops create GameFeatureData at <Plugin>/Content/<PluginName> + set_property Actions (instanced GameFeatureAction_AddComponents
    ComponentList entries, _AddCheats, _DataRegistry); activation is C++ only (UGameFeaturesSubsystem has no UFUNCTIONs) — python_exec unreal.GameFeaturesSubsystem is the runtime switch.
  - Composure (off by default): spawn_actor CompositingElement (or CompositingCaptureBase) + call_function CreateNewInputPass / CreateNewTransformPass (CompositingElementMaterialPass) /
    CreateNewOutputPass (RenderTargetCompositingOutput) — Inputs / TransformPasses / Outputs are protected instanced arrays, so never set_property them; SetTargetCamera picks the camera.
  - Sequencer Playlists (off by default, editor-only): asset_ops create SequencerPlaylist + set_property Items (SequencerPlaylistItem_Sequence: Sequence, NumLoops, PlaybackSpeed);
    playback is call_function PlayAll / StopAll on a SequencerPlaylistPlayer from the SequencerPlaylistsSubsystem.
  - Nanite Assemblies (5.8): the data is UStaticMesh NaniteSettings.NaniteAssemblyData (Parts with MeshObjectPath, Nodes with PartIndex and Transform) — set_property builds it by hand,
    or enable NaniteAssemblyEditorUtils and call_function NaniteAssemblyStaticMeshBuilder BeginNewStaticMeshAssemblyBuild / AddAssemblyPart / FinishAssemblyBuild.
  - Instanced Actors (off by default; Light Weight Instances are deprecated in 5.8): call_function InstanceActor(ActorClass, Transform, Level, Tags, ManagerClass) on the
    InstancedActorsSubsystem (editor-only) — the partition manager actor is created for you; RemoveActorInstance takes the handle back.
  - Code-level or external, not an asset an editor route could author: ML Deformer and Deformer Graph (trained models and compute graphs), the Unreal Animation Framework, Gameplay
    Targeting and Interactions (C++ task subclasses), State Graph and Scene State (experimental, no stable API), Learning Agents and NNE (training pipelines), Chaos Flesh (simulation
    assets from external solvers), Modular Vehicles (C++ vehicle sims), Network Prediction (C++ simulation model), Harmonix (MetaSound nodes — metasound_ops reaches them).

  Editor-UI or external, not something a route would improve on: Material Designer, Texture Graph, the Modeling tools' interactive brushes and mesh painting (ui_ops can drive the panels),
  Rewind Debugger, Object and Light Mixer (ui_ops opens the tabs), Audio Insights, Gauntlet and Automated Perf Testing (external drivers), nDisplay / DMX / Switchboard (hardware-facing).

  Still missing a route: nothing — every engine system above is either a tool, a recipe through the generic tools, or editor-UI / code-level by nature.
