# mcp-unreal

Rust MCP server (rmcp 3.2) + UE 5.8 C++23 editor plugin (`McpLink`, HTTP on 127.0.0.1:8091) giving AI agents full control of Unreal Engine, including PIE input injection.

## Layout
- `src/` — Rust server: `headless/` (Build.bat / UnrealEditor-Cmd subprocess tools, log parsers, .ini/.uproject editing), `editor/` (HTTP client and per-domain tools), `docs/` (engine-source class index + header parser + ripgrep search), `status.rs`, `schema.rs`, `update.rs` (self-update).
- `plugin/McpLink/` — UE editor plugin, C++23 via `CppStandard = CppStandardVersion.Cpp23`. Modules: `McpLinkCore` (HTTP server, route registry, `FMcpResponder`, log ring buffer, resolvers), `McpLinkEditor` (reflection / actors / levels / asset discovery and lifecycle / editor workflow / console / PIE / capture / perf and builds), `McpLinkInput` (per-frame input injection), `McpLinkBlueprint` (Blueprint, Anim Blueprint and Widget Blueprint assets and graph editing; the add_node vocabulary lives in `McpBlueprintNodes.cpp`), `McpLinkContent` (materials and material functions, render targets, textures and thumbnails, DataTables, Enhanced Input assets, ISM, Level Sequences and widget animations, Static Meshes, Sound Cues), `McpLinkWorld` (landscape terrain, foliage scatter, streaming sublevels, World Partition data layers and region loading, Level Instances and actor merging), `McpLinkAI` (Blackboards, Behavior Trees, State Trees and navigation queries; engine-facing helpers in `McpAiUtils.cpp`), `McpLinkWorkflow` (source control, Data Validation and Map Check, compile-all-Blueprints, gameplay tags, Curve asset keys, the reference graph), `McpLinkAnimation` (Montages, Blend Spaces, Aim Offsets and Composites; notifies, sync markers and curves via `UAnimationBlueprintLibrary`; skeleton sockets/virtual bones/slots; skeletal-mesh LODs and material slots; Physics Assets — engine-facing helpers in `McpAnimUtils.cpp`). Sibling interop plugins `plugin/McpLinkNiagara`, `plugin/McpLinkMetaSound`, `plugin/McpLinkMovieRender`, `plugin/McpLinkChaos`, `plugin/McpLinkGAS`, `plugin/McpLinkPCG`, `plugin/McpLinkPython`, `plugin/McpLinkToolsets`, `plugin/McpLinkGeometryScript`, `plugin/McpLinkControlRig`, `plugin/McpLinkLevelSnapshots`, `plugin/McpLinkIKRig`, `plugin/McpLinkRemoteControl`, `plugin/McpLinkLiveLink`, `plugin/McpLinkPoseSearch`, `plugin/McpLinkMass`, `plugin/McpLinkChooser`, `plugin/McpLinkCameras` (one Editor module each) depend on McpLink plus their engine plugin and register `/api/niagara/ops`, `/api/niagara/author`, `/api/audio/metasound`, `/api/render/movie`, `/api/chaos/ops`, `/api/gas|pcg/ops`, `/api/python/exec`, `/api/toolsets/*`, `/api/geometry/script`, `/api/anim/control_rig`, `/api/world/snapshot`, `/api/anim/ik_rig`, `/api/vp/remote_control`, `/api/vp/live_link`, `/api/anim/pose_search`, `/api/mass/ops`, `/api/data/chooser`, `/api/cameras/gameplay` (and McpLinkControlRig also registers `/api/anim/rigvm_graph`) through `FMcpLinkCoreModule::Get().RegisterRoute` at startup. RealtimeMesh is third-party and not part of the engine, so there is no interop for it.
- `test-project/` — minimal UE 5.8 project with an Enhanced Input character (`AMcpTestCharacter`, also an `IAbilitySystemInterface` with `UMcpTestAttributeSet` and two native gameplay effects for gas_ops E2E). `Plugins/McpLink*` are **junctions** to `plugin/McpLink*` (recreate with `pwsh -File tools/setup-dev.ps1`).
- `tools/mcp_call.py` — sequential MCP stdio driver used for E2E checks.

## Conventions
- Rust: tool routers per domain file via `#[tool_router(router = x_router, vis = "pub(crate)")]`; mega-tools are `#[serde(tag = "operation")]` enums carrying `#[schemars(transform = crate::schema::object_with_oneof)]`; all logging to stderr (stdout is JSON-RPC); errors carry remediation text; outputs capped via `budget.rs`.
- Plugin: every route handler runs on the game thread via `FMcpLinkCoreModule::RegisterRoute`; respond exactly once through `FMcpResponder` (`{"ok":true,"data":…}` / `{"ok":false,"error":{code,message}}` + a real HTTP status); all editor mutations need `FScopedTransaction`.
- **Two files in one module must never define the same anonymous-namespace helper**, and the same goes for two files whose named helper namespaces are opened with `using namespace` — merged into one translation unit, an unqualified call to a name both provide becomes ambiguous. Adaptive unity builds merge whichever files were not edited recently into one translation unit, so a duplicate name is a redefinition error that appears and disappears depending on file mtimes — it has broken the build twice. Shared helpers belong in `McpLinkCore` (`IntOr`/`DoubleOr`/`BoolOr` in `McpJson.h`, `ResolveWorldOrError` in `McpResolve.h`, `CallFunctionFromJson`/`FunctionSignatureJson` in `McpReflection.h`, `McpTestFlags` in `McpTestFlags.h`). `py -3 tools/scan-unity-collisions.py` lists candidates.
- The mirror image of that: unity builds also *hide* missing `#include`s, because a header pulled in by one file in the blob is there for every other file in it. `RunUAT BuildPlugin` — which `tools/package-plugin.ps1` runs to produce the release zip — compiles each file on its own, so those gaps only surface when a release is being cut. 21 files were relying on a neighbour for `Misc/PackageName.h`, `UObject/Package.h`, `EngineUtils.h` (`TActorIterator`) or `UObject/UObjectIterator.h` (`TObjectIterator`). Include what you use; the normal project build will not tell you — `Build.bat … -DisableUnity` does, compiling every file standalone in about three minutes, so run it before cutting a release (v0.3.0 packaging died on a `Cast<USkeletalMesh>` without `Engine/SkeletalMesh.h` that the unity build had hidden).
- Engine ground truth: verify UE APIs against the installed engine source before use (`Engine/Source` under your UE 5.8 install).
- Versions: the server and the plugin ship as one release and must never drift. The plugin's version comes from `McpLink.uplugin` through `IPluginManager` — never a `#define`, which `tools/bump-version.ps1` cannot see and CI now greps for. `status` compares the two and hints on a mismatch, and `update.rs` moves both halves or neither, because a server ahead of its plugin fails as a 404 on a route it is sure exists.

## Engine gotchas worth remembering
- Input injection uses `APlayerController::InputKey(FInputKeyEventArgs::CreateSimulated(...))`. The device id must come from `GetPrimaryInputDeviceForUser(PC->GetPlatformUserId())`, or `bFilterInputByPlatformUser` silently drops the event. Analog axes and mouse deltas must be re-injected every frame (`UPlayerInput` consumes its accumulator per frame) and mouse axes need `NumSamples >= 1`; digital keys latch until released.
- `FEditorDelegates::EndPIE` fires while `GEditor` still reports a live session — report the post-transition state rather than snapshotting mid-teardown.
- A multicast delegate's `Remove()` **destroys the bound lambda immediately**, even when called from inside that delegate's own broadcast: `FDelegateBase::Unbind` runs the instance's destructor right there, and only the invocation-list *compaction* is deferred while `InvocationListLockCount > 0`. So a one-shot handler that unbinds itself must not touch its own captures afterwards — take them by value (`FinishCapture` does) or copy them to locals before the `Remove` (`CompleteOnPieEvent` does). Reading them anyway is a use-after-free on the captured `TSharedRef` itself, which surfaces as an access violation at `0xffffffffffffffff` somewhere far away — it looked like `FMcpResponder::Send` freeing a responder, which is not what happened. `FTSTicker::RemoveTicker` is the opposite and is safe: it only marks the element's state, leaving the lambda alive for the rest of the call.
- Never call `AActor::BeginPlay()` by hand; it trips the begin-play state ensure and corrupts the actor. Use a separate init helper called from both `BeginPlay` and `SetupPlayerInputComponent`.
- Reference assets in constructors with `ConstructorHelpers::FObjectFinder`, not `LoadObject`.
- Spawn graph nodes with `FGraphNodeCreator<T>` and configure them (e.g. `SetFromFunction`) *before* `Finalize()`, so pins are allocated from the real signature. Link pins via the schema's `CanCreateConnection`/`TryCreateConnection`, never `MakeLinkTo` directly.
- A header's first match for `class Foo` is often a forward declaration; use the indexed macro line to find the real definition.
- Unexported K2 node classes (`UK2Node_CreateWidget` is in UMGEditor's *private* headers, `UK2Node_PlayMontage`, `UK2Node_LatentGameplayTaskCall`, `UK2Node_LatentAbilityCall`, the `UK2Node_Get{Engine,Editor}Subsystem` / `…FromPC` variants are `UCLASS()` with no API macro) spawn fine through `FGraphNodeCreator<ExportedBase>::CreateNode(true, FindObject<UClass>(nullptr, "/Script/Module.Class"))`; their protected proxy fields (`ProxyFactoryFunctionName`, `ProxyFactoryClass`, `ProxyClass`) are plain UPROPERTYs, so `FindFProperty` + `SetPropertyValue_InContainer` does what the engine's own menu spawner lambda does. `UK2Node_PromotableOperator::SetFromFunction` is an unexported virtual override — call it through a `UK2Node_CallFunction*` and it dispatches. `FTypePromotion::GetOperatorSpawner(Op)->GetFunction()` is whichever overload registered first (`Multiply` came back as "Seconds * FrameRate"); pick the all-`double` overload from `GetAllFuncsForOp` for the title. `UK2Node_GenericCreateObject` refuses, at compile time, anything abstract (`UDataAsset`), `DontUseGenericSpawnObject` (`USaveGame`, `UUserWidget`), or an Actor/component — check up front. `FKismetEditorUtilities::CanCreateBlueprintOfClass(UBlueprintFunctionLibrary)` is false; the function-library factory skips it. Validate everything an add_node kind needs *before* `FGraphNodeCreator::Finalize()`, or a refused request leaves an orphan node that fails the next compile.
- `UMaterialEditingLibrary::SetMaterialInstance{Scalar,Vector,Texture}ParameterValue` always return `false` in 5.8 (`bResult` is never assigned). Validate the parameter name against `Get*ParameterNames` before calling, and never treat the return as a failure signal.
- `FJsonObjectConverter` camelCases property names by default; pass `EJsonObjectConversionFlags::SkipStandardizeCase` so tool output matches the names an agent passes back in.
- `UTexture2D::GetSizeX/Y` are 0 under `-nullrhi` (no platform data); fall back to `Texture->Source.GetSizeX/Y`.
- Slate runs under `-nullrhi`: windows and widget trees exist (so `ui_query` works headless), nothing is rasterised (so `capture_viewport` does not).
- AutomationDriver: its synchronous API dispatches every step with `AsyncTask(GameThread)` and blocks on the future, so calling it *from* the game thread deadlocks — drive it on a worker thread and defer the response. Its path parser asserts rather than erroring on a malformed selector: a leading `/` makes an empty first piece and reaches `Matchers.Last()` on an empty array, a trailing `/` reaches `PathPiece[0]` of an empty string, and both die on `Array.h`'s range check and take the editor with them — validate before handing a path over. Path syntax is `<SType>` for a widget type, `#Id` for a driver id, a bare word for a tag, `/` for a direct child and `//` for any descendant. `FindElement` resolves only a locator that matches exactly one widget and reports nine matches identically to none, so collect with `FindElements` and index. Widgets are located through *arranged* geometry, which `-nullrhi` never produces, so this needs a windowed editor.
- `CreateWidget` refuses the base `UUserWidget` class ("Abstract, Deprecated or Replaced classes are not allowed"); a runtime-built UMG tree needs a concrete subclass, e.g. `UMcpTestHudWidget`.
- The default pawn's `BeginPlay` can run before possession; do local-player setup (mapping context, HUD) from a helper called from both `BeginPlay` and `SetupPlayerInputComponent`.
- Anim state machines: `FGraphNodeCreator<UAnimStateNode/UAnimStateTransitionNode/UAnimGraphNode_StateMachine>` + `Finalize()` runs `PostPlacedNewNode`, which creates the bound graph; then `Transition->CreateConnections(From, To)`. Name states with `FBlueprintEditorUtils::RenameGraphWithSuggestion(BoundGraph, FNameValidatorFactory::MakeValidator(Node), Name)` (clashes become `Idle_1`). Every transition rule graph is literally named `Transition` under its own node, so McpLink addresses it as `<From> to <To>` in graph paths.
- UMG authoring: `FWidgetBlueprintOperationUtils` (UMGEditor, new in 5.8) is the programmatic designer — `CreateWidgetBlueprint`, `AddWidget`, `MoveWidget`, `RemoveWidget`, `RenameWidget`, `WrapWidgets`, `ReplaceWidgetWithTemplate`, `BindToEventProperty`. A bound event needs the widget as a variable on the *skeleton* class: `ToggleWidgetAsVariable` + `MarkBlueprintAsStructurallyModified` (which runs a skeleton-only compile) before `BindToEventProperty`. `FKismetNameValidator` accepts spaces and punctuation, so check `FName::IsValidXName(Name, INVALID_OBJECTNAME_CHARACTERS)` yourself. `FPackageName::IsValidLongPackageName` rejects `/Temp/` unless `bIncludeReadOnlyRoots`. `FJsonObjectConverter::JsonObjectToUStruct` on a UObject gives partial nested-struct updates, FText from a string and enums by name; `UStructToJsonObject` with `CheckFlags = CPF_Edit, SkipFlags = CPF_InstancedReference` dumps editable properties without recursing through a slot's `Parent`/`Content`.
- Undo vs PIE: anything recorded in the transaction buffer during PIE pins the PIE world and `EndPlayMap` asserts ("Object … from PIE level still referenced … TransBuffer"). `Modify()` on a PIE object inside an `FScopedTransaction` does it, and so does *creating* an `RF_Transactional` object while a transaction is open (`StaticConstructObject_Internal` records it) — e.g. `call_function` on a CDO that spawns a widget. Pass `McpLink::ShouldTransact(Object|World)` as `FScopedTransaction`'s second argument, and never transact `call_function` while `GEditor->PlayWorld` is set.
- `UWidgetBlueprintLibrary::Create` is `BlueprintInternalUseOnly`, so Python has no `unreal.WidgetLibrary.create`; show an authored widget in PIE with `call_function` on `/Script/UMG.Default__WidgetBlueprintLibrary` `Create` + `AddToViewport`.
- AnimGraph classes are `MinimalAPI`: only `ANIMGRAPH_API`-marked members and virtuals are callable; access UPROPERTYs directly. Sub-graphs live in `UEdGraph::SubGraphs` (state machine → states/transitions), not in the Blueprint's graph arrays.
- Asset-registry tag values (`ParentClass`, `TargetSkeleton`) are export text (`/Script/Engine.Skeleton'/Game/X.X'`); run them through `FPackageName::ExportTextPathToObjectPath`.
- Niagara: `UNiagaraFunctionLibrary::SpawnSystem*` returns null when `FApp::CanEverRender()` is false (`-nullrhi`), so Niagara spawning can only be verified in a windowed editor. User parameters live in `System->GetExposedParameters()` under `User.<Name>`; type them with `FNiagaraTypeDefinition::Get*Def()` comparisons before calling `SetVariable*`. A system compiles on first use (seconds): right after spawn the component reports inactive/complete and `IsReadyToRun()` false, then activates itself — report `system_ready` rather than treating that as failure.
- GAS: attribute enumeration is `UAttributeSet::GetAttributesFromSetClass` (static on the set, not on `FGameplayAttribute`); instant effects return an invalid `FActiveGameplayEffectHandle` by design. A default-subobject `UAttributeSet` on the owner is picked up by the ASC automatically.
- PCG: `UPCGGraphInstance::UpdatePropertyOverride(Property, bOverride)` takes two args (the three-arg one is on `FPCGOverrideInstancedPropertyBag`); `Generate()` is asynchronous, so poll `IsGenerating()`. `NewObject<UPCGGraph>` in a package is a valid graph asset (input/output nodes come from the constructor).
- Python plugin: `ExecuteStatement` is `Py_single_input` (one interactive statement) — multi-line source must run as a file (`ExecuteFile`); on failure the traceback is in `CommandResult`, not `LogOutput`. `EHttpServerResponseCodes` has `NotSupported` (501), no `NotImplemented`.
- Material graph: most `FExpressionOutput`s are unnamed (channel masks), so `UMaterialEditingLibrary::ConnectMaterialExpressions` by output name only reaches output 0; link other outputs with `FExpressionInput::Connect(Index, Expression)`. Expression options are UPROPERTYs — edit them with set_property on the expression path.
- Level Sequences: frames on the wire are *display-rate* frames (what the Sequencer timeline shows); `UMovieScene` stores tick-resolution frames, so every time crosses `FFrameRate::TransformTime`. `ULevelSequence::Initialize()` + `SetTickResolutionDirectly`/`SetDisplayRate` is all `ULevelSequenceFactoryNew` does, so no LevelSequenceEditor dependency is needed. `UMovieSceneSequence::CreatePossessable` is public on the base class (the `ULevelSequence` override is protected) and already handles parent bindings and dedup. 5.8 spawnables are possessables carrying a custom binding — `FindSpawnable` returns null for them, so a `UMovieSceneSpawnTrack` is what identifies one. Single-channel sections leave `FMovieSceneChannelMetaData::Name` unset, which stringifies to "None"; McpLink calls that channel "Value". Section object names restart per track, so two tracks both hold a `MovieScene3DTransformSection_0` — address sections by path.
- Niagara compile status: `UNiagaraSystem::PollForCompilationComplete` returns false both while a compile runs *and* when there was nothing to compile, so it is not a completion signal. Read `HasOutstandingCompilationRequests()` plus each script's `GetVMExecutableData().LastCompileStatus` / `LastCompileEvents`. `IsReadyToRun()` is unconditionally false when `FApp::CanEverRender()` is false, i.e. always under `-nullrhi`.
- Niagara stack surgery: `FNiagaraStackGraphUtilities::AddScriptModuleToStack`, `SetModuleIsEnabled`, `GetStackFunctionInputs` and `GetOrCreateStackFunctionInputOverridePin` are exported, but `GetOrderedModuleNodes`, `RemoveModuleFromStack` and `GetModuleIsEnabled` are not. A stack is a chain of `UNiagaraNodeFunctionCall`s threaded through the pin whose `PinSubCategoryObject` is `FNiagaraTypeDefinition::GetParameterMapDef().GetStruct()`, ending at the output node — walk it for order, relink it to remove. `UNiagaraNodeParameterMapSet` (the node holding a module's input overrides) is in NiagaraEditor/Private, so match it by `/Script/NiagaraEditor.NiagaraNodeParameterMapSet`. A Niagara bool is a 4-byte `FNiagaraBool`, not a C++ `bool`.
- Niagara module inputs: `FNiagaraStackFunctionInputBinder` can only write a local value and refuses ("Input is overridden in the stack") any input whose override pin is linked — which is every input a template handed to a dynamic input. The editor's own stack view model is the way in: `FNiagaraSystemViewModel` with `bIsForDataProcessingOnly = true` (plus `bCanAutoCompile/bCanSimulate/bCompileForEdit = false`, `MessageLogGuid = System.GetAssetGuid()`) is what the audit commandlet and the user-parameter helpers build — no preview component, no sequencer, no undo registration, works under `-nullrhi`, and its exported destructor runs `Cleanup()`, so a per-request instance is fine. `TNiagaraViewModelManager::GetExistingViewModelForObject` is *not* reachable (the `ObjectsToViewModels` specialisation has no export). Walk `GetSystemStackViewModel()` / `GetEmitterHandleViewModelForEmitter(...)->GetEmitterStackViewModel()` → `GetRootEntry()` → `GetUnfilteredChildrenOfType<UNiagaraStackModuleItem>(…, true)`; under a module item every `UNiagaraStackFunctionInput` at any depth is an input, owned by the function-call node `GetInputFunctionCallNodePtr()` returns (the module, or a dynamic input node), which is how the tree nests. Skip `UNiagaraStackModuleItemLinkedInputCollection` / `…OutputCollection` subtrees. `GetValueMode`, `GetLocalValueStruct`, `SetLocalValue` (replaces a dynamic input or link, as the panel does), `SetDynamicInput`, `SetLinkedParameterValue[ViaConversionScript]`, `SetCustomExpression`, `SetDataInterfaceValue[External]`, `Reset`, `SetEditConditionEnabled`, `GetAvailableDynamicInputs` and `GetAvailableParameters` are all exported and each opens its own transaction. Niagara's enums are user-defined enums whose entries are literally `NewEnumerator0…`; `UEnum::GetDisplayNameTextByIndex` is the only name the editor shows. `SuggestName` on a freshly made dynamic input node is ignored once it has a name, and renaming it would orphan the `<Name>.<Input>` override pins beneath. A template's data interface override can be named `Scale Alpha.FloatCurve` — a '.' inside an object name that no object path can address, so DI edits go through the view model (`SetDataInterfaceValueExternal` + `FJsonObjectConverter`), never `set_property`. `FJsonObject::Values` keys are `UE::TSharedString` in 5.8 (`Pair.Key.ToView()`, no `ToString`).
- A freshly constructed `UAnimMontage` already carries a `DefaultSlot` track, `UAnimMontage::AddSlot` appends unconditionally, and `IsValidSlot` answers "has segments" rather than "exists" — so find the slot by name first or you get two slots with one name. `CalculateSequenceLength()` only computes; store it with `SetCompositeLength()` or the montage stays zero-length. `FCompositeSection` links via the base `FAnimLinkableElement::Link(Sequence, Time)`; there is no `SortSections`.
- `USkeleton::AddNewNamedVirtualBone` silently returns false for any name without the engine's virtual-bone prefix — run names through `VirtualBoneNameHelpers::AddVirtualBonePrefix` first.
- `UBlendSpace::BlendParameters` is protected with only a const getter, so axis edits go through the reflected `FStructProperty` (`ContainerPtrToValuePtr<FBlendParameter>(BlendSpace, Axis)`), which is what the details panel writes anyway.
- `USkeletalMeshEditorSubsystem`'s members are `static`, so there is no subsystem instance to fetch. Its `CreatePhysicsAsset` picks its own asset path; `FPhysicsAssetUtils::CreateFromSkeletalMesh` (with `bShowProgress=false`, or a headless editor hangs on the dialog) is the one that takes a package you chose.
- `ULevelInstanceSubsystem::CreateLevelInstanceFrom` hardcodes `bUseSaveAs = true` on the streaming level it builds, so it always opens a Save As dialog. A `-nullrhi` editor cannot draw it and wedges on the game thread — still listening on 8091, never answering, no crash dump. The route refuses when `FApp::CanEverRender()` is false. `UEditorLevelUtils::FCreateNewStreamingLevelForWorldParams` *does* expose `bUseSaveAs`, so plain sublevel creation works headless; its `DefaultFilename` is a filesystem path, not a package path.
- `AActor::GetComponents(TArray&, bool)` **resets** its output array, so accumulating across actors needs a temporary per actor. `IMeshMergeUtilities::MergeComponentsToStaticMesh` prefixes the asset name with `SM_`, turning a base name of `SM_Thing` into `SM_SM_Thing`.
- Moving a streaming level needs `FLevelUtils::SetEditorTransform`; assigning `ULevelStreaming::LevelTransform` alone leaves the loaded actors where they were.
- `FValidateAssetsDetails::ValidationMessages` holds `FTokenizedMessage`s, not `FText`; `ValidationWarnings` is the `FText` list. `UEditorValidatorSubsystem` and `IGameplayTagsEditorModule` live in the DataValidation and GameplayTagsEditor *plugins* (both enabled by default), so `McpLink.uplugin` lists them as required alongside `EnhancedInput`.
- MetaSounds are documents, not EdGraphs: `UMetaSoundBuilderSubsystem` creates a builder, `UMetaSoundEditorSubsystem::BuildToAsset` turns it into an asset, and `FindOrBeginBuilding` gets a builder back for an existing one. Node classes are `Namespace.Name[.Variant]` — enumerate them with `Metasound::Frontend::ISearchEngine::Get().FindAllClasses(EResultVersion::Highest)` (both `INodeClassRegistry::IterateRegistry` and the bool overload of `FindAllClasses` are deprecated). `RegisterGraphIfOutstandingTransactions` is protected; `UMetaSoundEditorSubsystem::RegisterGraphWithFrontend` is the public equivalent, and an edit that is not registered is not what the next load sees.
- `World->SpawnActor` on an `AVolume` subclass leaves `Brush` null, so the volume encloses nothing — a Nav Mesh Bounds Volume placed that way silently builds an empty nav mesh and Map Check says "collision component with 0 radius". `UActorFactory::CreateBrushForVolumeActor(Volume, Builder)` is the editor's own fix and is exported; `spawn_actor` calls it.
- State Trees have no EdGraph: the editor draws `UStateTreeState` objects, so authoring is just building the hierarchy and running `FStateTreeCompiler`. `FStateTreeCompilerLog::Messages` is protected — read it with `ToTokenizedMessages()`. The editor data needs a concrete `UStateTreeSchema` or nothing is legal to add, and `StateTreeEditorModule` pulls in `PropertyBindingUtils` for `FStateTreeBindableStructDesc`'s base destructor.
- EQS: `UEnvironmentQueryGraph::UpdateAsset` builds `UEnvQuery::Options` from the graph, and opening an asset whose `EdGraph` is null creates an *empty* graph rather than rebuilding one from the options — so options authored directly are discarded on the next open. The graph must be authored. Its classes are plain `UCLASS()` in the EnvironmentQueryEditor *plugin* with no API macro, so nothing links, but nothing needs to: `FindObject<UClass>(nullptr, TEXT("/Script/EnvironmentQueryEditor.EnvironmentQueryGraphNode_Option"))` gets the class, `NewObject<UAIGraphNode>` makes the node, and `PostPlacedNewNode`, `AllocateDefaultPins`, `UpdateAsset`, `CreateDefaultNodesForGraph` and `TryCreateConnection` are all virtual overrides of exported bases, so calling them through `UAIGraphNode`/`UAIGraph`/`UEdGraphSchema` dispatches into the plugin. `ClassData` must be set before `PostPlacedNewNode` (it is what builds `NodeInstance`, a `UEnvQueryOption` carrying the generator), and `bTestEnabled` is a UPROPERTY defaulting to true. This is the general escape hatch for any unexported editor module.
- Running an EQS query needs no PIE: `UEnvQueryManager::GetCurrent(World)` comes off the world's `UAISystem`, and editor worlds are created asking for one (`UWorld::InitializationValues(...).CreateAISystem(InWorldType == EWorldType::Editor)`), so `RunInstantQuery` answers against the level as it is open. The manager keeps a *duplicate* of every template it has run, cached by full asset name, so an edited query re-runs as its pre-edit self unless `UEnvQueryManager::NotifyAssetUpdate` drops that cache (it is `AIMODULE_API` and static, behind `USE_EQS_DEBUGGER`). In the single-item run modes the result is not one item: `FEnvQueryInstance::bDebuggingInfoEnabled` defaults to true, and `PickSingleItem` then keeps the whole scored set and swaps the winner to index 0 — so the pick is item 0, and `Items.Num()` is the debugger's set. Only `AllMatching` trims to the items that passed. A `UEnvQueryTest` straight out of its constructor is `FilterAndScore` over the range 0..1, so a distance test added and left alone filters out everything more than one unit away.
- Profiling readback: `stat <group>` toggles go through `UE::Stats::DirectStatsCommand(Cmd, /*bBlock*/ true)` — no viewport needed, and the stats thread gathers headless — and `FLatestGameThreadStatsData::Get().Latest->ActiveStatGroups[i]` (indexed like `GroupNames`, which are `STATGROUP_*`) holds the `FComplexStatMessage` aggregates the overlay draws: cycle stats via `FPlatformTime::ToMilliseconds(GetValue_Duration(EComplexStatField::IncAve))`, counters by `NameAndInfo.GetField<EStatDataType>()`. `FStatGroupGameThreadNotifier::Get().StatGroupNames` is the registry `stat help` prints. `MemReport` defers itself (`MemReportDeferred`) to the end of the frame and writes to a *dated subfolder* of `Saved/Profiling/MemReports/`, so find the new file recursively. `FCsvProfiler::EndCapture` returns a `TSharedFuture<FString>` for the path; a capture started with a frame count ends itself and `GetOutputFilename()` is empty afterwards.
- Screenshots: an editor viewport's `ProcessScreenShots` broadcasts the bitmap on `FScreenshotRequest::OnScreenshotCaptured()`, the game viewport's on `UGameViewportClient::OnScreenshotCaptured()` — bind both for a high-res shot (`GetHighResScreenshotConfig().SetResolution` + `FScreenshotRequest::RequestScreenshot(false)` + `FViewport::TakeHighResScreenShot()` + `Invalidate()`, drawn on the next frame; the engine still writes its own copy under `Saved/Screenshots`). `FlushRenderingCommands` lives in `RenderCore`, which a module has to list to link it.
- `FLandscapeImportHelper` (LandscapeEditor module) is exported: `GetHeightmapImportDescriptor` + `GetHeightmapImportData` read a 16-bit PNG / raw / r16 through the registered landscape file formats, `TransformHeightmapImportData` resamples or pads to a target resolution, and `ChooseBestComponentSizeForImport` is the New Landscape panel's layout choice.
- Sequencer events: `FMovieSceneSequenceEditor::Find(Sequence)->GetOrCreateDirectorBlueprint(Sequence)` (Sequencer module, exported) makes the director Blueprint the way the panel does — a Level Sequence's lands at `<Sequence>:<Name>_DirectorBP`, which `blueprint_modify` addresses as-is. `FMovieSceneEventUtils::BindNewUserFacingEvent(&Event, Section, DirectorBP)` (MovieSceneTools) creates the custom event in the "Sequencer Events" graph, wires the bound-object pin for a binding's track and sets the endpoint; the `FMovieSceneEvent*` must point into the section (`EventChannel.GetData().GetValues()[Index]` after `AddKey`, or a repeater's `Event`). - Landscape edit layers: every 5.8 landscape has them (`HasLayersContent` is deprecated and returns true). Height and weight writes through `FLandscapeEditDataInterface` land in whatever `ALandscape::GetEditingLayer()` names — `FScopedSetLandscapeEditingLayer` sets it for a scope — and the layers are merged into the final heightmap on the GPU, which `LandscapeEditLayers.cpp` gates on `FApp::CanEverRender()`: under `-nullrhi` a layer write is kept but `get_heights` never sees it. With no editing layer set, the write goes straight into the final textures and the next merge overwrites it. `ULandscapeEditLayerBase` (`GetEditLayer(index|name|guid)`) carries name, visibility, lock and per-target alpha with exported setters; `CreateLayer`, `DeleteLayer`, `ReorderLayer`, `ClearLayer`, `SetEditingLayer` are on `ALandscape`.
- Landscape splines: `ULandscapeSplineControlPoint` / `ULandscapeSplineSegment` are MinimalAPI, so `UpdateSplinePoints`, `AutoCalcRotation` and `GetBestConnectionTo` do not link — but both classes' `PostEditChangeProperty` override calls `UpdateSplinePoints` (and `RequestSplineLayerUpdate` on `ValueSet`), and `DeleteSplinePoints` is virtual, so build the objects by hand (`NewObject` outered to the `ULandscapeSplinesComponent`, `Connections[0/1].ControlPoint`, `TangentLen`, `ConnectedSegments.Add(FLandscapeSplineConnection(Segment, End))`, the component's `GetControlPoints()` / `GetSegments()` arrays) and dispatch those through the vtable. `ALandscapeProxy::CreateSplineComponent()` makes the component; `ULandscapeInfo::ApplySplines()` (no-argument overload; the `bOnlySelected` one is deprecated) is Apply Splines.
- Runtime Virtual Textures: `RuntimeVirtualTexture::SetBounds(Component)` (VirtualTexturingEditor, public) is the details panel's Set Bounds; `IVirtualTexturingEditorModule` has `BuildStreamedMips(EShadingPath, Component)`, `HasStreamedMips` and `GatherRuntimeVirtualTextureComponents(World)`. `ARuntimeVirtualTextureVolume::VirtualTextureComponent` is private — `FindComponentByClass`. Primitives and landscape proxies hold their `RuntimeVirtualTextures` array as a UPROPERTY; reflection (`FArrayProperty` + `FScriptArrayHelper`) edits it without caring about visibility.
- Media Framework: `UMediaPlayer::Play/Pause/Seek/SetRate` go through `FMediaPlayerFacade::SetRate`, which refuses a rate the player's controls do not list; with `-nosound` the WMF player lists none, so a headless editor opens a file (`ready`, duration and tracks arrive) but refuses to play. `UFileMediaSource` resolves a `./`-relative path against the project's Content directory.
- Cube and volume textures are just `FTextureSource::Init` with the slice count: six slices on a `UTextureCube` make a cube map (one slice is read as a long-lat panorama), `Depth` slices on a `UVolumeTexture` make the volume. `UTexture` has no generic `GetPixelFormat`; each class has its own.
- Exporting by format: `UExporter::RunAssetExportTask` with a `UAssetExportTask` (`bAutomated = true`, `bPrompt = false`, `Exporter = nullptr`) picks the exporter from the filename's extension and collects `Errors`; `IAssetTools::ExportAssetsWithCleanFilename` only ever takes the first exporter registered for the class. The glTF Exporter plugin is enabled by default in 5.8, so `gltf` / `glb` are available without touching the project.
- The Bash tool unescapes backslash sequences inside heredocs (`\\n` in a quoted heredoc reaches the file as a real newline, `\n` in Python source becomes a line break). Never patch C++ string literals through a Bash heredoc; use the Edit/Write tools for any text containing backslashes.
- The Bash tool fails to parse very long commands (a ~20 KB heredoc died with "unexpected EOF"); write big files with the Write tool.
- Bash: never put a variable assignment on the same `&&` chain as a backgrounded (`&`) command — the whole chain runs in a subshell and the variable is lost.
- Headless automation: `UnrealEditor-Cmd` only mirrors its log to stdout with `-stdout -FullStdOutLogOutput`; without them stdout is just child-process (UBT) chatter. Never chain `;Quit` after `Automation RunTests` — it races the final test and its result is lost; use `-TestExit=Automation Test Queue Empty`. The on-disk `Saved/Logs/<Project>.log` can be truncated on fast exit, so parse stdout first and treat the file as a fallback.
- 5.8 automation log shape: `Test Completed. Result={Success|Fail} Name={Short} Path={Full.Dotted.Path}`; per-test events follow completion inside `BeginEvents: <path>` / `EndEvents:`; `Automation List` output is `LogAutomationCommandLine: Display: <tab>Name`.

## Self-update gotchas
- Rust's `std::fs::symlink_metadata(..).file_type().is_symlink()` is true for a Windows **junction**, not only a real symlink — verified against `test-project/Plugins`, which `tools/setup-dev.ps1` creates as junctions. That single check is what stops an update writing through a development checkout, so do not replace it with a `FILE_ATTRIBUTE_REPARSE_POINT` test that would need `#[cfg(windows)]`.
- Windows refuses to write or delete a running `.exe` but allows **renaming** it, which is the whole self-replace trick: move the running binary to `<name>.old`, rename the new one into place, delete the leftover at the next start. The rename cannot cross a filesystem, so the incoming binary has to be unpacked next to the target, not in the cache directory.
- GitHub's release API carries a per-asset `digest` of the form `sha256:<hex>` (the reason `release.yml` ships no `.sha256` sidecars) — but only on assets uploaded recently enough, so treat it as absent-tolerant. `/repos/{owner}/{repo}/releases/latest` answers **404 while the repository is private**, drafts included, which is also what "no releases yet" looks like. Auto-update therefore does nothing until this repo is public, unless `MCP_UNREAL_UPDATE_TOKEN` is set.
- The updater is exercised against a mock release built from real assets: `tools/mock-release.py` renames the published v0.1.0 assets as a newer version and serves them, and `MCP_UNREAL_UPDATE_API` points the server at it. `MCP_UNREAL_UPDATE_DIR` redirects the state and staging directory, so a test run touches nothing real. Never let a test reach `install_server`: it replaces `std::env::current_exe`, which under `cargo test` is the test binary.

## Build & test
- CI lints on Linux, so a `#[cfg(windows)]`-gated helper whose only callers are also gated becomes dead code there and fails `-D warnings`. Prefer a runtime `cfg!` so every branch stays compiled, and check before pushing with `cargo clippy --lib --target x86_64-unknown-linux-gnu -- -D warnings` (no linker needed for a lib check). Since the updater added rustls, that cross-check also builds `ring`, whose C needs a compiler for the *target* — without one it dies in `cc-rs` with `failed to find tool "x86_64-linux-gnu-gcc"`. `zig` is one, but cc-rs appends `--target=<rust triple>` and zig only parses `x86_64-linux-gnu`, so its own defaults have to be turned off: `CRATE_CC_NO_DEFAULTS=1 CC_x86_64_unknown_linux_gnu="zig cc -target x86_64-linux-gnu" AR_x86_64_unknown_linux_gnu="zig ar" CFLAGS_x86_64_unknown_linux_gnu="-O2 -fPIC" cargo clippy --lib --target x86_64-unknown-linux-gnu -- -D warnings`.
- Rust: `cargo build`, `cargo test` (60 tests: parser fixtures in `tests/fixtures/`, `*_ue58.log` captured from the real toolchain; contract fixtures in `tests/fixtures/contract/`).
- Plugin automation tests live in each module's `Private/Tests/` (`McpLink.*`, 22 tests). Run them through the tool itself: `run_tests {"filter": "McpLink"}` (~20s headless). Kill any headless editor first — two plugin instances fight over port 8091.
- Plugin: `"<UE>\Engine\Build\BatchFiles\Build.bat" McpTestEditor Win64 Development -Project="<repo>\test-project\McpTest.uproject" -WaitMutex`
  - Live Coding in any *other* open editor blocks UBT globally; add `-NoHotReloadFromIDE` to build anyway.
- Contract fixtures (`tests/fixtures/contract/`) are the shared Rust/plugin contract: one captured request+response envelope per file, checked by `tests/contract_tests.rs` (request bodies the tools build, envelope unwrapping) and by `McpLink.Core.Contract.Fixtures` (routes still registered, envelope still what `FMcpResponder` emits). **Capture them, never hand-write them:** `py -3 tools/capture_contract.py <spec.jsonl>` against a running editor.
- Headless editor for E2E: `UnrealEditor-Cmd.exe <project> -nullrhi -unattended -nopause -nosplash -nosound -stdout -FullStdOutLogOutput` (up on 8091 in ~8s); windowed, for capture/render checks: `UnrealEditor.exe <project> -nosplash -unattended` (~10s, plus ~20s before the viewport draws). Kill with `taskkill //IM UnrealEditor-Cmd.exe //F` (or `UnrealEditor.exe`) before rebuilding — the DLL is locked — and before `run_tests`, which starts its own. UBT skips a source edited *during* a build whose object file it then writes (the .obj ends up newer), so `touch` the file and rebuild if a change seems to have no effect.
- E2E: `py -3 tools/mcp_call.py <calls.jsonl>` against a running editor. One `{"name":…,"arguments":{…}}` per line; `{"sleep": 1.5}` lets the game tick. Requests are served concurrently, so never pipeline dependent calls.
- `capture_viewport` and `render_ops` need a windowed editor (`-nullrhi` has no viewport and no RHI to draw with); `level_instance_ops create` needs one too, because the engine hardcodes a Save As dialog. Everything else works headless.
